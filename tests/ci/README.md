# OpenWrt 25.12 CI tests

This directory contains an **active, manually triggered** QEMU test harness for an official OpenWrt 25.12.5 x86_64 system image.

- `openwrt-25.12-qemu.sh` downloads the official ext4 image, verifies its pinned SHA-256, boots it under QEMU, checks release metadata and `apk`, installs a temporary test dependency inside the disposable VM, runs BusyBox syntax checks, offline diagnostic smoke tests, incident-state tests, bounded foreground monitor tests, RAM-worker simulations, a mocked read-only WAN path-audit test and a mocked RU/international HTTPS endpoint-survey test, then executes one real `check` probe. The guest also performs **real procd start/stop/restart tests** using a deterministic mock `check` inside the disposable VM (no service on any physical router).
- `workflow-openwrt-25.12.yml.example` is a reference copy of the active workflow at `.github/workflows/openwrt-25.12.yml`. Only `workflow_dispatch` is enabled, with no `push`, `pull_request` or scheduled triggers.
- The job has a 12-minute timeout, one x86_64 VM, no runner cache and no uploaded artifacts. Guest serial logs are printed in the job log for debugging.
- The guest runs isolated inside GitHub Actions: **no real router is touched**.
- The VM checks guest userland/CLI compatibility, not MediaTek/Cudy drivers, real-world ISP restrictions, Podkop integration or network path independence.
- The selected OpenWrt image is pinned to 25.12.5; updating the release requires updating both its URL and checksum in the runner script.

**Run #4 infrastructure failure, not a code-test failure (2026-10-23):** [GitHub Actions run #4](https://github.com/SVTagan/owrt-netguard/actions/runs/40029556683) stopped at `apk update` inside the disposable OpenWrt VM before any new offline test executed. The `x86_64/base/packages.adb` feed returned a `wget` transport error (`Operation not permitted`, incomplete index). The newly added `netguard-profile-probe` therefore **was not evaluated by that run**. Afterward, `tests/ci/openwrt-25.12-qemu.sh` was changed to run syntax + deterministic offline tests before any package installation and to attempt `apk update && apk add curl ca-bundle` up to 3 times with a short delay. If all attempts fail, CI still fails with an explicit infrastructure message; the failure is not silently treated as a passing product test. **The modified workflow was rerun successfully as run #5.**

**Run #5: SUCCESS (2026-10-23).** [Full log](https://github.com/SVTagan/owrt-netguard/actions/runs/40030153822): 16 diagnostic smoke scenarios, 55 state transitions, bounded monitor and worker, route audit, endpoint survey, profiles with actual guest UCI, **grouped profile HTTPS synthetic cases**, one-shot `HEALTHY_SAMPLED`, and full procd lifecycle. The reordered offline tests completed before the curl installation; the apk feed succeeded on its first attempt. The new grouped probe still needs real field tests on AX6000/OpenWrt 24.10.5. No test establishes ISP fault attribution or the absence of nftables/PBR interception.

**DNS regression (run #6: PASS):** [Run #6](https://github.com/SVTagan/owrt-netguard/actions/runs/40032413103) passed the isolated `netguard-dns-probe` syntax and deterministic mocked DNS/router tests in OpenWrt 25.12.5 BusyBox `ash`, before apk installation, together with all prior regressions and real legacy `HEALTHY_SAMPLED`/procd checks. The isolated DNS command was subsequently tested on physical AX6000/OpenWrt 24.10.5: localhost, Yandex and SkyDNS all returned `ANSWER` in the `russia` profile. These results do not prove the identity of external resolvers, DoH health or direct WAN delivery. Passing mocks does not prove that plaintext UDP/53 reaches the intended server or that DNS failure implies ISP failure.

**Next WAN-only regression (not yet run):** New opt-in `netguard-wan-check` + `tests/wan-check.sh` are now included in guest-RAM copy, OpenWrt BusyBox syntax checks and deterministic smoke suite **before apk**. It enforces pinned-IP-only, two-primary-target quorum, ignores allowlist-only success for RU health, and maps errors into the existing worker `RESULT:` contract. The grouped profile sampler also now begins both curl variants with `-q` and rejects a successful pinned transfer when `remote_ip` differs from the requested pinned IPv4. Legacy `owrt-netguard check`, worker, state library and procd script remain unchanged. This new revision **has not been run in QEMU**, and there is **no physical AX6000 test yet**.

Reference: https://openwrt.org/docs/guide-user/virtualization/qemu

**Security:** Only use the default empty root password in the disposable, isolated test VM, never on a real Internet-exposed OpenWrt system.
